# bsl-syntax-help-mcp — кодекс проекта (карта минных полей)

Docker-сервисы (FastAPI/FastMCP + SQLite, SentenceTransformers-эмбеддинги) и
плагин выгрузки синтакс-помощника для 1С:EDT (Maven/Tycho, Eclipse OSGi).
Этот файл — **чего НЕ делать** и **где остановиться и подумать дважды**.
«Как делать правильно» — в [DEVELOPER.md](DEVELOPER.md) и
[CHECK-FLOWS.md](CHECK-FLOWS.md). Claude Code загружает файл автоматически;
opencode — из AGENTS.md.

## ❌ Жёсткие «нельзя» (нарушение = утечка данных или сломанная сборка)

1. **Секреты и данные в git не коммитить:** `docker/*/.env`
   (токены `INGEST_TOKEN` / `MCP_TOKEN`), `connector/bom/edt-credentials.env`
   (учётка реджестри 1С), `docker/mcp/data/` и `*.sqlite` (корпус),
   `docker/giga/hf-cache/` (веса, ~13 ГБ). Всё уже в `.gitignore` — не убирать.
2. **`EXPECTED_EMBED_DIM=2048` (`docker/mcp/app/config.py`) жёстко связан с
   моделью Giga-Embeddings-instruct.** Хранимые в SQLite векторы не пересчитать
   без полной переиндексации: смена модели/размерности без миграции ломает
   гибридный поиск (FTS при этом продолжает работать).
3. **Контракт ingest: `POST /ingest/begin` → `POST /ingest/batches` (карточки
   батчами ~200) → `POST /ingest/commit`, поле `layer`.** Менять только вместе:
   плагин (`IngestClient.java`), FastAPI (`app/ingest.py`), README, пример в README.
4. **Границы токенов не смешивать:** `/ingest/*` и `/admin/*` — `INGEST_TOKEN`;
   любой метод `/mcp` (включая GET/DELETE) — `MCP_TOKEN`;
   `/health`, `/ready`, `/status`, `/` — без токена.
5. **Не перезаписывать `help.sqlite` под живым контейнером MCP** — WAL-SQLite
   портится. Замена файлов только при остановленном MCP.
6. **Версии пакетов 1С в `MANIFEST.MF` не фиксировать** (`Import-Package` без
   `version`): один исходник собирается под EDT 2025.2 (Eclipse 2025-12) и
   EDT 2026.1 (`-Pedt-2026.1`).
7. **XML-entity лимиты уже в `connector/.mvn/jvm.config`** — Maven подхватывает
   их сам (склеивает с MAVEN_OPTS). Дублировать в env не нужно.
8. **MCP не запускать рядом с HelpSearchServer** — коллизия имён инструментов
   (`docinfo` / `docsearch`).

## 🛑 Зоны «стоп и подумай дважды» (большой радиус поражения)

| Где | Почему опасно | Перед правкой |
|---|---|---|
| `docker/mcp/app/db.py`, `app/ingest.py` | WAL-режим, сессии ingest (`begin/batches/commit`), чекпоинт при коммите; ошибки = испорченный корпус | Прогнать полный цикл begin→batches→commit на пустой БД; убедиться, что повторная выгрузка того же слоя идемпотентна |
| `docker/mcp/app/embedder.py` | Префикс инструкта применяется только к запросам (`EMBED_QUERY_PREFIX`); асимметрия запрос/документ | Не добавлять префикс к документам; проверять `/ready` в `degraded` без Giga |
| `docker/mcp/app/search.py`, `app/chunking.py` | Гибрид FTS5 + sqlite-vec, разбиение страниц на чанки; влияет релевантность и `doc_id`-ссылки | Сверить `docinfo`/`docsearch` на известных карточках до и после |
| `docker/mcp/app/versions.py` | Слои (`base`, `8.3.25`…`8.5.1`) — контракт с чекбоксами плагина | Новый слой = правка в плагине (`Layers.java`) + README |
| `Plugin` (`SyntaxHelpPlugin.java`, `ExportJob.java`) | Читает `PlatformDocProvider` (`getTree` + `loadPage`); API зависит от версии EDT | Собрать оба профиля: `bash compile.sh` и `--profile edt-2026.1` |

## ⚠️ Известные ловушки окружения

- **Установка p2 из архива:** флажок «Обращаться во время инсталляции ко всем
  сайтам обновления…» должен быть **снят**, иначе p2 лезет на `services.1c.dev`
  (ошибка аутентификации), а локальные артефакты не находит
  (`No repository found containing`).
- **«Все элементы установлены»** = в zip тот же квалификатор, что уже стоит.
  Пересоберите (`bash compile.sh`) или удалите фичу в
  `Справка → О программе → Сведения об установке` и ставьте заново.
- Первый старт Giga: `/health` держит 503, пока модель не в VRAM
  (`start_period` в compose — 30 минут). Это не поломка.
- Учётные данные репозитория EDT — `bom/settings.xml` +
  `bom/edt-credentials.env` (в CI — секреты `MAVEN_USERNAME` /
  `MAVEN_CENTRAL_TOKEN`). Никогда не коммитить реальные значения.

## 🧪 Уровни проверки (знать, что доказывает какой)

- **Ярус 0 — сборка:** `bash compile.sh` → BUILD SUCCESS + свежий квалификатор
  в имени zip. Python-часть отдельно: `docker compose -f docker/mcp/docker-compose.yml up --build`.
- **Ярус 1 — тесты:** пока нет (план — логика чанкинга/поиска, клиент ingest).
- **Ярус 2 — живая установка:** p2 в EDT 2025.2 → «Выгрузить» в настройках →
  `curl /status` (слои и счётчики выросли) → `docsearch` находит известную карточку.
- **Ярус 3 — e2e в CI (headless EDT через `p2 director`):** план.

Зелёный нижний ярус НЕ доказывает верхний.

- **Проверяй существование класса/метода/переменной окружения** grep'ом/чтением,
  прежде чем ссылаться.
- **Коммиты — локально по умолчанию;** push только по явной просьбе.
  Деструктивные действия (`DELETE /admin/*`, чистка `hf-cache/`, стоп контейнеров

- **Ветки:** работа в `develop` (или `feature/*` от неё); `main` — только merge из
  `develop` под релиз; теги `X.Y.Z` ставятся только на `main` (см. DEVELOPER.md,
  workflow `release.yml` — релиз собирается сам по пушу тега).
- **Сборку гонять `compile.sh`**, а не собирать команду из головы; если сборка
  упала — чинить причину, а не обходить флагом.
- **README.md обновлять вместе с поведением** (установка, сервисы, контракт
  ingest); сборка, ветвление и релизы живут в `DEVELOPER.md` — его тоже.
- Не оставлять после себя мусор: `target/`, `bin/`, `__pycache__/` в gitignore,
  `docker/mcp/data/` локально — ожидаемая часть окружения, не репозитория.
